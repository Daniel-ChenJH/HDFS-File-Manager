# Design

Developers switch between source code and HDFS during their working day; the editor's selected theme controls every surface and contrast choice.

Use VS Code theme variables, font and font size. Restrained layout: native tree, compact connection selector, path navigation, breadcrumbs beside folder filtering, a file table and a quiet status/footer. No dashboard cards, promotional copy or decorative animation. One Settings entry owns all configuration. Save & open checks and saves the connection. Global preferences validate and save independently as they change.

Buttons use pill shapes, inputs use a 9px radius and dialogs 12px. Standard buttons are 30px high, inputs 32px, data rows 34px; icons use a consistent 16px stroke system. Settings use two columns on wide views and one below 700px. Long names truncate visually, retaining their extension and accessible full titles; path fields scroll. File-type icons identify common formats in the list, preview and tree. Narrow layouts hide secondary metadata, keeping file actions and counts available. Loading reserves row space; file actions disappear while a different folder loads. Sort and paging keep keyboard focus. Preview opens without rebuilding the retained file list. File information closes through its close control, Escape or a click on the backdrop, returning focus to the original control.

Light, dark and high-contrast colors inherit the editor. The original icon uses a restrained folder/network mark. Controls have visible focus, keyboard navigation and reduced-motion support. Supporting connection explanations live in help/advanced disclosure sections rather than the browsing view.

The entire file row is a selection target. Single-clicking a file previews it alongside the list; folders open on double-click or Enter. Row actions remain independent. Preview occupies the browsing area below 800px and has a return control and Escape shortcut that restore the selected row. Up has a visible text label; Backspace and Alt+Up go to the parent, while Alt+Left/Right navigate history. Preview limits and supported formats live in settings help and actionable limit messages.

PDF pages scroll vertically as one document, with a compact page-number shortcut. Only nearby pages render; the page positions remain available for scrolling. No extracted-text section appears below the document.

Routine successful actions do not show banners or completion toasts. Saving a connection is an explicit check workflow: a cancellable modal, then a result confirmed before opening. Loading ends when results are ready; saving clears the unsaved indicator. Save & open remains available when unchanged. Failures use one concise message with the actions needed to recover. Download location stays explicit in the chooser and progress. Product text and controls use no emoji; icons are SVG or editor-native theme icons.

Save & open validates the draft, lists the starting directory and reads one byte from an available non-empty file before saving. Separate save and diagnosis buttons are omitted; timeout is directly visible. No diagnostic action or fixed read-only badge occupies the browsing surface. The connection menu owns Disconnect. Error actions follow the actual category; settings shortcuts focus the related field. Settings has a left-side return arrow that restores the previous list or preview, including filter, path draft and scroll. From preview-limit settings, the back arrow returns directly to the originating file using the saved limit. Unsupported formats prioritize downloading and omit a redundant second preview action. The header host describes where requests run, independently of the download destination.

Dropdown menus use the editor theme, align below the trigger or above it when needed, and leave the trigger and its label visible. All support keyboard navigation, type-ahead, Escape and outside-click dismissal. Numeric settings use quiet minus/plus controls. Preview format guidance is always visible; each limit has a brief hover/click information tooltip. The wrap toggle changes both icon and selected color. Text encoding lives beside it in the preview. The page-size selector lives beside the footer page indicator, defaults to 50 and offers 10/20/50/100/200; it is not a Settings field.

Cancelling folder navigation restores the last successful rows and their paging/filter/scroll context. Errors and pending paths belong to their connection and disappear when that connection is removed. Adding or switching a connection preserves any unfinished global preference input. Download target Home/End choose the first/last target, and asynchronous folder lookup preserves target focus. Delayed filename tooltips never replace an open menu. Escape cancels an in-progress connection check; result dialogs still require confirmation.

File management is available by default. The connection form's Read only switch (仅只读) starts off, including for older connections. When enabled and saved, write actions disappear and the host rejects them. A tooltip by the label explains the affected operations and the preview-only content workflow. Upload and New folder sit on the left; Favorites and Transfers sit on the right, using matching pill buttons. Each row has a star toggle. Favorites opens a dedicated list and returns to the highlighted item in its parent directory. Row checkboxes and modifier selection preserve ordinary single-click preview and double-click folder navigation. Selection survives paging and clears on folder, connection or filter changes.

Upload source and download destination pills name This computer or the actual SSH alias. Pickers execute on the selected host. Uploads show the HDFS target before submitting. Directory and batch downloads choose a destination once and preserve structure. If a file conflict is found, the editor asks once which action to apply to matching files in the task. The transfer panel has a fixed header and a separately scrolling list. Detailed failed-item lists remain behind an explicit action. Batch tasks do not create one notification per file. Routine creation and renaming update the list without success dialogs. Permanent deletion uses a short confirmation with the selected path or item count.
