# Architecture

The extension declares `extensionKind: ["workspace"]` and uses VS Code's stable API (minimum 1.109). It runs in the local extension host for local windows and the remote extension host for SSH windows. No web extension entry point is provided. This editor minimum supplies Node 22.21.1, meeting the bundled HTTP client's Node 22.19 minimum in both local and remote hosts.

`src/client.ts` implements WebHDFS reads with bundled Undici and writes with dedicated Node HTTP(S) agents, routed directly from the extension host. Writes construct the public Node ClientRequest with a dedicated agent, so editor patches to high-level request functions cannot reroute them. They handle informational 100 Continue responses from DataNodes. CREATE performs the NameNode Location negotiation before streaming data; MKDIRS, RENAME and DELETE check boolean responses. The connection Read only flag is checked before any write request. Each path segment is encoded separately. Redirects are followed up to five hops; cross-origin Basic/Bearer forwarding and HTTPS downgrade are prohibited. Server response bodies and request URLs never appear in errors. Streaming transfer writes an exclusive temporary sibling, checks size and cancellation, then renames atomically. The original destination survives transfer failure.

`src/model.ts` owns configuration validation, path normalization, the four-operation concurrency gate and last-request-wins cancellation. `src/extension.ts` owns SecretStorage, globalState, tree, webview messages and dialogs. Non-secret connection data is explicitly projected before persistence. No configuration contributions duplicate the settings page.

`src/downloads.ts` coordinates the single-file destination dialog and shares a two-file transfer gate with batch uploads and downloads. `web/download.js` places host/local pills above the folder path, keeps each target's draft and rejects stale target/chooser responses. The preference defaults to the extension host; local windows always resolve that to the user's computer. A temporary pill switch does not change the saved default.

`companion/package.json` declares a local UI extension with `api: "none"`, included via the main manifest’s `extensionPack`. The workspace extension checks the companion through the stable cross-host command API. Without a working local companion, the transfer UI offers the SSH host as the only location. The receiver handles native local file/folder selection, bounded source reads and destination writes; no endpoint, username, password or token crosses to it. There is no extra server, port, SSH process or whole-file buffer. `src/client.ts` awaits each 1 MiB chunk acknowledgement, bounding queued bytes. `src/transfer.ts` verifies size and an incremental SHA-256 digest, locks destinations, and writes exclusive temporary siblings. It preserves the existing destination on cancellation/failure, checks for external changes before committing, and expires orphaned transfers after two idle minutes. Cancellation at the local progress notification also signals the workspace host to abort HDFS reading.

`web/app.js` provides paged directory browsing and settings using vanilla DOM APIs, with `textContent` for all user/server strings. The host retains at most one paged listing; only the current 200 rows cross into the webview. Native tree lists are bounded to 1,000 visible entries. Webviews can load only bundled resources. They never receive connection credentials.

`src/listing.ts` filters and sorts only that retained listing. Listing revisions and individual page-request IDs prevent old responses from replacing newer navigation, sort or filter results. Connection and preference forms commit independently; failed connection persistence restores the previous secret. A download captures its client before opening the save dialog, is cancelled when connections change, and locks its destination until completion. Previewing a file keeps the directory panel and its scroll/focus state intact.

`src/preview.ts` supplies the same bounded reads to the inline pane and the optional editor preview tab. Each surface retains only its current file; request IDs and abort controllers reject cancelled or superseded results. Navigating, disconnecting, opening settings or closing the pane releases the inline preview. Text is bounded to 1–4 MiB and media to 1–50 MiB in the settings UI. SVG and HTML are treated as inert source text. No remote file is executed or opened through a shell.

`src/text-encoding.ts` decodes UTF-8, UTF-16LE/BE and GBK using the host's TextDecoder. Automatic mode checks UTF-16 BOMs, then validates UTF-8; other encodings require an explicit choice. ASCII and ISO-8859-1 are decoded explicitly because WHATWG labels otherwise alias them to Windows-1252. Truncated previews omit partial terminal characters, while malformed complete input offers an encoding correction. Switching encoding cancels the previous read and keeps the standalone panel. Original downloads bypass decoding.

PDF.js runs in a local Blob worker. `web/pdf-scroll.js` arranges pages in a continuous scroll viewport, renders nearby pages sequentially at the pane's display size and retains at most six canvases. Distant canvases are released; switching files cancels rendering and disconnects observers. Bundled webview entry points and minified PDF resources reduce SSH resource loading. A webview caches the PDF module and worker source; each preview surface reuses its worker across files while destroying the previous document and invalidating its rendering. A failed engine is disposed without waiting for abandoned transport cleanup; closing the webview terminates the worker. PDF previews do not extract page text or read sidecar metadata. Fonts and CMaps ship with the extension.

`web/text-view.js` lazily loads the CodeMirror view/state core as a read-only viewport. Long lines and large line counts are virtualized; no syntax parser, editing commands or autocomplete is loaded. Wrapping and copying preserve the received text, including CRLF and JSON integers. Its generated style sheet uses the webview's CSP nonce. Closing or switching the preview destroys its view and observers.

`web/bytes.js` decodes PDF base64 into a single preallocated byte buffer in 64 KiB encoded chunks. It yields after about 1 MiB of decoded bytes and checks whether the preview is still current. This avoids a large intermediate JavaScript number array and keeps cancellation actionable during decoding.

PDF.js 6.5.438 uses a 16 MiB image-resizing canvas budget in the worker and requests reduced JPEG dimensions from the native decoder where supported. Its compatibility build includes upstream polyfills for the supported editor runtime floor. Rendered pages use at most 3,520,000 pixels each, with a 16,384px height limit; the area budget preserves long-page detail. These limits do not cap total process memory or every decoder's temporary buffers. The compressed file size is not a bound on decoded pixels.

Image-decoding WebAssembly, ICC profiles, fonts and CMaps are bundled. The CSP permits WebAssembly compilation for these local decoders; JavaScript eval remains disabled. PDF scripting and QuickJS assets are not shipped. The optional PDF.js renderer worker is disabled because this viewer schedules and recycles its own canvases; parsing and image decoding retain the existing dedicated worker.

Connection save checks run against the draft before persistent settings or credentials change. The progress modal carries a request generation, cancellation aborts network work, and stale replies cannot replace a later attempt. Empty-directory success explicitly excludes file reading. A local companion command obtains the SSH alias from public remote workspace URIs; visible host labels never use the operating-system hostname. Connection storage scope stays unchanged to preserve existing configurations. An empty native tree is replaced with a theme-aware welcome webview using a centered SVG and Settings button.

During replacement navigation the host retains its last successful listing until the new read commits. The webview keeps only its currently displayed page and navigation context for cancellation recovery. This permits continued paging after cancellation without a directory-history cache. Connection mutations clear pending paths and old error context; independent preference drafts survive edits to the connection form. Popup management cancels pending filename timers when another control opens.

## File management and transfer tasks

`src/tasks.ts` coordinates transfer manifests, a two-operation shared transfer gate, bounded task history, failure ledgers and explicit retry. `src/file-access.ts` authorizes source and destination roots through native pickers, uses opaque grants for later operations, checks path containment and symlink traversal, and enumerates local directories in batches. Each file read is at most 1 MiB. The source companion never receives HDFS credentials. Browser messages contain metadata, not upload bytes.

The task plan is emitted to disk before copying begins. In-memory history is capped at 50 tasks, pending tasks at 20, retained selection metadata at 16 MiB, per-task plans at 32 MiB and transfer metadata at a 128 MiB budget. Metadata reservation failures stop the task; file sizes have no preview-derived limit. These bounds are not total process-memory guarantees. Retry reads manifest lines incrementally and reauthorizes sources/destinations after interruption. Connection identities are bound to jobs to prevent retrying an old plan against a different endpoint.

Downloads use temporary destination siblings and size/SHA-256 verification. Directory structure and empty directories are retained; symlinks are skipped. Uploads use unique HDFS temporary siblings. Replacing a file retains the original under a unique backup name until commit succeeds. A durable journal survives ambiguous rename responses. Ordinary upload cancellation cleans the uncommitted temporary object; failed cleanup or ambiguous replacement remains available for explicit reconciliation. No task resumes automatically on editor restart.

Favorites are scoped by connection ID. Opening a favorite requests the page containing its name in the sorted parent listing. Changes made through the extension update matching favorite paths. Text search uses CodeMirror's read-only search controls. The optional JSON formatter validates token grammar and emits original scalar lexemes, retains duplicate keys, yields while working and caps formatted output. It never sends formatted text back to HDFS.
